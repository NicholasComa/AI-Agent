# Qdrant 核心概念

Qdrant 是一个开源的向量数据库，专门用于存储向量并做相似度检索。在 RAG 系统中，它负责保存知识库片段的向量与元数据，并在查询时快速返回最相似的若干条记录。

## Collection 集合

Collection 是 Qdrant 中的数据表，类似于关系数据库中的表。一个集合用于存放一类向量数据，例如一个知识库对应一个集合。创建集合时需要指定向量的维度（vector size）和距离度量（distance），例如使用余弦相似度作为度量。同一个集合内的所有向量必须维度一致，否则无法写入。

## Point 点

Point 是 Qdrant 中最小的数据单元，每条 Point 由一个唯一 id、一个向量（vector）和可选的负载（payload）组成。可以把 Point 理解为表中的一行：id 是主键，vector 是参与检索的数值，payload 是附属的描述信息。写入数据的过程就是把一个个 Point upsert（插入或更新）到集合中。

## Vector 向量

Vector 是 Point 中参与相似度计算的核心字段，通常是嵌入模型输出的浮点数组。向量的维度由集合创建时确定，写入的向量维度必须与之匹配。检索时，Qdrant 把查询向量与集合中的所有向量按照指定的距离度量进行比较，返回最接近的若干条。

## Payload 负载

Payload 是附着在 Point 上的附加结构化数据，可以存储任何 JSON 兼容的内容，例如来源文件名、片段序号、正文文本、标题等。Payload 不参与向量相似度计算，但可以在检索后随结果一起返回，也能作为过滤条件使用。在 RAG 中，payload 通常用来保存片段的原文和溯源信息，便于生成阶段引用。

## Filter 过滤

Filter 是 Qdrant 的过滤机制，允许在相似度检索的同时按 payload 字段做条件筛选。例如「只检索来源为某篇文档的片段」或「只检索某个章节编号范围内的片段」。过滤条件可以组合使用，支持等于、范围、包含等多种运算符。过滤发生在向量检索之前或之后，能够显著缩小候选范围、提高精度。

## Local Mode 本地模式

Local Mode 是 Qdrant 的一种轻量运行方式，数据直接存储在本地内存或本地文件目录中，不需要启动独立的服务进程，也不需要 Docker。Local Mode 适合开发和单元测试，因为它在进程内即可运行、零外部依赖。与 Docker 模式相比，Local Mode 的功能是子集，但足以覆盖 Collection、Point、Payload、Filter、Search 等核心能力。

## Docker 部署

生产环境通常用 Docker 部署 Qdrant，作为一个独立的服务进程对外提供 HTTP 与 gRPC 接口。客户端通过主机地址和端口连接该服务。Docker 部署的好处是数据持久化、可水平扩展、支持多客户端并发访问，适合作为长期运行的知识库后端。开发阶段可以先在 Local Mode 验证逻辑，再切换到 Docker 部署。
